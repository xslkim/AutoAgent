版本：v0.2 · 2026-11-16 · 状态：方案，待确认（见 §12）。给执行模型的详细任务文档在本方案确认后另写，§10 是大纲。

## 1. 边界

### 1.1 已确认的选择（2026-11-16）

| 项 | 决定 |
|---|---|
| 风格 | 风格化低模，平涂色板，无贴图 |
| 角色 | 五种人形用分件刚体；Boss 用骨骼片段 |
| 来源 | 场景和通用道具程序化；角色、Boss、重点道具走生成路线，各有程序化保底；购买兜底 |
| 花费 | 本地优先；线上和购买合计 500 元以内 |
| 授权 | 内部验证，记录并遵守适用许可 |
| 硬件 | 按安卓电视盒子预算制作，PC 运行同一套 |
| 审核 | 四批：道具、场景、角色、Boss，各审一次 |

### 1.2 与引擎方案的关系

- 引擎方案的首版是白模，明确不引入外部素材。本方案是它之后的阶段，在引擎任务 T20 完成、用户对玩法方向给出判断之后开始接入。框架工具的搭建不依赖游戏，可以提前做。
- 白模关卡文件 `warehouse_raid.json` 要到引擎任务 T18、T19 才产生。本文的资产清单依据引擎方案里的表格估算，关卡文件出来后要按实际数据更新一次（任务 WR00）。
- 美术不改变玩法：命中体、阻挡体、站位、时间一律沿用白模。唯一的例外是 Boss 的骨骼片段（§6），它会让命中体移动，按框架 §3.5 的“影响玩法”处理。

### 1.3 需要引擎配合的改动

这些改动在 `game/` 下，除 EI05 外都不碰 Sim。它们是接入任务，不属于资产制作，但没有它们资产进不了游戏。

| 编号 | 改动 | 说明 |
|---|---|---|
| EI01 | 美术数据独立存放 | 新增 `game/data/art/warehouse_raid.art.json`：资产映射、颜色、区域光照表。画面层读它，Sim 不读。引擎现在把角色颜色写在 `archetypes.json` 里，而这个文件的哈希会进回放，所以改颜色会让回放失效。在这里覆盖表现颜色，保留archetypes.json原字段及原始值不动，避免改变旧回放哈希 |
| EI02 | 美术开关 | 命令行 `--art=on\|off`。关闭或资产缺失时退回白模图元。测试：同一条回放在两种模式下最终哈希相同 |
| EI03 | 画面层加载资产网格 | 角色按（兵种，部件）、道具和拾取物、投射物按类型查资产映射，替换图元网格。位置和部件变换仍来自 Sim |
| EI04 | 场景画面层加载区块 | 开启美术时加载场景区块 GLB，不再按白模几何生成盒子。阻挡体仍来自关卡文件 |
| EI05 | 姿态库支持查表 | Sim 的 `pose_lib` 增加从姿态轨取部件变换的来源，按框架§17把姿态轨放game/data/poses，生成pose_data_sha256并入回放校验。这是唯一改 `sim/` 的一项，接入后重新生成回放夹具 |
| EI06 | 移动档渲染配置 | 命令行可选 Compatibility 渲染器；两种材质（顶点色不计光照、顶点色加一盏平行光）；区域光色随镜头插值；角色脚下的圆形暗片；关闭环境光遮蔽 |
| EI07 | 视点与视线导出 | 开发工具：从关卡轨道导出视点集，从关卡校验器导出“相机到暴露弱点”的视线清单，供框架的检查使用 |

引擎方案目前只验收 Forward+ 渲染器，并写明切换到 Compatibility 需要另做验证。目标硬件改为安卓电视之后，这项验证就落在 EI06 上。它是本方案最大的外部依赖，见 §12。

## 2. 美术方向

### 2.1 一句话

夜间的工业仓库，低模、硬朗、色块分明：场景是低饱和的冷灰，敌人是高饱和的色块，弱点一律是琥珀色。

参考方向是早期街机光枪游戏的平涂多边形角色（关节分段、色块明确、轮廓夸张），加上现代的烘焙光照和干净的配色。

### 2.2 设计语言

玩家要靠这几条规则在一两秒内读懂画面，所有资产都服从它们：

| 规则 | 表达 |
|---|---|
| 打这里最有效 | 琥珀色。敌人的头、Boss 的导弹舱和核心。全关没有别的东西用这个色系（奖章除外，见 §2.4） |
| 这是敌人 | 高饱和的躯干色，每个兵种一个 |
| 打这里没用 | 中性钢灰。盾、Boss 装甲。有意接近场景金属色 |
| 不能打 | 蓝色躯干、无头盔、无装备。只有人质用蓝色 |
| 会爆炸 | 橙色。油桶、投掷兵、手雷 |
| 打了有好处 | 绿色（医疗）、金色（奖章）、带绿色束带的木箱 |
| 场景 | 低饱和，不抢色。每个区域有一个主光色，帮助感知“到了新地方” |

不使用任何文字和标志。需要标识的地方用条纹、箭头、色块。

### 2.4 色板自查结果

按框架 §5.1 和 §10 的规则计算（CIELAB 色差）：

| 检查 | 结果 |
|---|---|
| 所有颜色 Y′ ≤ 0.70 | 通过，最高 0.69 |
| 场景色饱和度 ≤ 0.40 | 通过，最高 0.36 |
| 各兵种识别色两两色差 ≥ 25 | 通过，最小是射手对盾兵 27.3 |
| 人质蓝对任一敌人 ≥ 35 | 通过，最小 56.2 |
| 敌人头部对自己躯干 ≥ 20 | 通过，但投掷兵只有 22.0，余量小 |
| 玩法色对最近的场景色 ≥ 18 | 射手 43、冲锋兵 47、投掷兵 49、盾兵 20.3、人质蓝 25.2、人质头 21.6、弱点 54、油桶 51、补给箱 25.1、医疗绿 50、奖章 57。医疗包十字的浅灰 13.7，不达标 |

需要说明的五点：

1. **投掷兵的头和躯干色差小**。所有敌人的头和躯干之间加一圈深色领口（`gear`，与头部色差 76），用明度差把头分出来，不只靠色相。
2. **盾兵和人质头部的余量小**（20–22）。它们在实际背景上是否够醒目，由渲染检查 R01 在每个站位上判定，不达标时调整该站位背后的场景色，而不是改角色。
3. **医疗包十字的浅灰接近场景的浅金属色**。十字面积很小，医疗包的识别色是绿色，检查 M03 对它豁免。
4. **装甲色与场景金属色几乎相同**（Boss 装甲对钢结构的色差 1.4）。这是有意的：装甲要读作“打不动”。Boss 和盾兵靠体型、弱点的琥珀色和红色条纹从背景里分出来，是否足够同样由 R01 判定。
5. **奖章的金色与弱点琥珀色差 9.6**，投掷兵的橙与油桶的橙色差 11.6。前者的含义都是“打它”，后者都是“会爆炸”，属于同一条设计语言，不算冲突。检查 M03 对奖章豁免。

补给箱和装饰纸箱除了颜色（色差 25），还从形状上分开：补给箱有木板条和绿色束带，装饰纸箱不做成 0.7 米的正方体。

## 3. 目标硬件与预算

按框架 §9 的移动档。屏幕上的尺度：内容区 1776×936、视场 60° 时，每米的像素数约为 810 ÷ 距离。5 米处 162 像素每米，11 米处 74，Boss 所在的 12 米处 68。由此，角色身上小于约 3 厘米的独立细节在 11 米处不到 2 像素，不做。

每帧预算的分配：

| 项 | 三角形 | 绘制调用 | 依据 |
|---|---|---|---|
| 场景区块 | ≤ 55,000 | ≤ 6 | 同时可见 2–3 个区块 |
| 人形角色 | ≤ 10,000 | ≤ 72 | 同屏最多约 8 个，每个 ≤ 1,200 面、最多8个部件，加脚下暗片 |
| Boss | ≤ 6,000 | ≤ 20 | 10个部件加装饰件 |
| 道具、拾取物、投射物 | ≤ 6,000 | ≤ 20 | |
| 特效 | ≤ 5,000 | ≤ 20 | |
| 界面 | — | ≤ 10 | |
| 合计 | ≤ 82,000（上限 100,000） | ≤ 148（上限 150） | |

绘制调用在普通战斗段的最坏情况下接近上限，原因是分件刚体每个部件一次调用。真机不达标时的对策是引擎把相同的部件网格合批，不需要改资产。

单个资产的面数预算：

| 资产 | 面数 |
|---|---|
| 人形：头 150、躯干 250、手臂 90、腿 110、手持物 80、盾 60 | 全身 ≤ 1,200 |
| Boss：躯干 1,200、腿 500、髋 500、导弹舱 500、炮 400、头 300、核心 200、盖板 100、装饰 800 | 全身 ≤ 6,000（左右腿及左右导弹舱分别计数；装饰预算包含在总额内） |
| 油桶 300、补给箱 200、医疗包 120、奖章 80、手雷 100、导弹 150 | |
| 重点道具（叉车、垃圾箱等） | ≤ 2,000 |
| 场景区块 | 每个 ≤ 20,000 |

这些数值是估算，没有真机数据。见 §12。

## 4. 场景

### 4.1 做法

全部程序化，按框架 §7.6 在 Blender 里依据关卡文件组装、烘焙光照、按区域导出区块。白模的每个实心几何体对应一个模块，模块的实体体积与白模体一致。

五个区块：

| 区块 | 范围（z） | 覆盖的段 | 主光色 | 内容 |
|---|---|---|---|---|
| alley | 0 到 −22 | S0–S2 | 暖黄 | 两侧高墙、垃圾箱、木箱堆、管线、一盏壁灯、夜空 |
| dock | −22 到 −44 | S2–S4 | 冷蓝 | 卷帘门、装卸平台、钢走道和栏杆、叉车、箱子 |
| aisle | −44 到 −64 | S4–S6 | 绿 | 两侧各 4 组货架、层板上的纸箱、尽头的箱堆 |
| office | −64 到 −82，含夹层 | S6–S8 | 橙红 | 楼梯、夹层地板、办公桌、文件柜、带窗洞的隔断 |
| boss_dock | −84 到 −112 | S8–S10 | 冷白，带红色警示灯 | 开阔地面、四周的集装箱 |

### 4.2 模块清单

程序化生成脚本，每个脚本一种模块，尺寸和细节由参数控制：

| 脚本 | 参数与细节 |
|---|---|
| `gen_wall` | 尺寸；类型（混凝土板、波纹铁皮）；踢脚、接缝、壁柱 |
| `gen_floor` | 尺寸；接缝网格、排水沟、斜坡 |
| `gen_shutter_door` | 门洞尺寸、门框厚度；卷帘条纹、卷筒盒 |
| `gen_platform` | 尺寸；防撞条、台阶 |
| `gen_walkway` | 长度、高度；支柱、格栅面、栏杆（栏杆不挡弹） |
| `gen_stairs` | 起点、终点、级数；梯梁、扶手 |
| `gen_shelf` | 宽、高、层数；立柱孔、斜撑、层板上的货物摆放（随机种子） |
| `gen_container` | 2.4×2.6×6；波纹、门杆、角件；四种颜色 |
| `gen_box_stack` | 占用体积；箱子大小和错位（随机种子）；不生成 0.7 米正方体 |
| `gen_pallet` | 标准托盘 |
| `gen_partition` | 尺寸、窗洞位置；窗框 |
| `gen_pipes` | 路径点；管径、卡箍、阀门 |
| `gen_lamp` | 类型（壁灯、吊灯、警示灯）；灯罩是发光件 |
| `gen_backdrop` | 巷道上方的夜空渐变和远处建筑剪影 |

重点道具走生成路线，程序化版本保底：垃圾箱（2.0×1.2×1.0，S1 的掩体）、叉车、办公桌、文件柜。它们都是掩体或阻挡体，生成的网格必须配准到白模体，检查 C04 不过就用保底版本。

### 4.3 规则

- 掩体的可见边缘与阻挡体的边缘一致。敌人从掩体后探身时，玩家瞄的是这条边。
- 不挡弹的装饰只有栏杆、管线、吊灯、货架上的小件。它们不得挡住任何“相机到敌人暴露弱点”的视线（检查 C07）。走道栏杆在投掷兵站位处尤其要注意。
- 窗洞、货架缺口这类“可以射穿”的地方，视觉上必须是明确的空洞。
- 烘焙光照：每个区域一盏主光加少量补光，颜色见上表。暗部不要死黑，敌人站位处的背景亮度要和敌人的识别色拉开，由检查 R01 判定。
- 顶点色烘焙和光照贴图两种做法，在场景批次里用 alley 区块各出一份样张，由用户选一种用于全部区块。

## 5. 人形角色

### 5.1 做法

分件刚体，姿态沿用引擎姿态库的公式，美术只影响画面。部件表来自引擎任务 T09 和 T11：

| 部件 | 命中基元 | 命中区 |
|---|---|---|
| head | 球，半径 0.17，中心高 1.60 | 弱点 |
| torso | 盒 0.46×0.62×0.26，中心高 1.12 | 身体 |
| arm_l / arm_r | 胶囊，半径 0.07，总高 0.60 | 身体 |
| leg_l / leg_r | 胶囊，半径 0.09，总高 0.82 | 身体 |
| gun | 盒 0.08×0.10×0.40 | 不参与命中 |
| shield（盾兵） | 盒 0.70×1.20×0.08 | 装甲 |

这套比例是大头、粗四肢，约五头身，像玩具兵。概念图必须按这个比例画，写实比例的角色切开后配不上命中体。

制作路线：每个兵种出正面加侧面的概念图 → 整体生成 → 按身高 1.77 米对齐 → 在颈部（高 1.43）、髋部（高 0.82）、肩部（左右 0.23）切开 → 每个部件配准到自己的基元。选型测试表明生成路线对人形不可用时，改为拼装：用程序化的部件生成脚本（多棱柱四肢、带切面的躯干、几种头盔）组合。

四肢左右镜像，各兵种尽量共用；头、躯干、手持物每个兵种单独做。

### 5.2 各兵种

每个兵种除了颜色，还要有不靠颜色也能认出的轮廓特征：

| 兵种 | 躯干色 | 头（琥珀色） | 躯干与装备 | 手持 | 轮廓特征 |
|---|---|---|---|---|---|
| 射手 | 红 | 平顶头盔，带护目镜的切面 | 战术背心，胸前弹匣袋 | 步枪 | 标准体型，横持长枪 |
| 冲锋兵 | 紫 | 兜帽加面罩，前尖 | 轻装，无背心，肩窄 | 砍刀（占用 gun 部件的位置） | 瘦，手里是刀不是枪 |
| 投掷兵 | 橙 | 圆头盔 | 斜挎弹带，背后小背包 | 手雷 | 背部鼓出，斜向的弹带 |
| 盾兵 | 锈褐 | 防暴头盔带面罩 | 厚重的护甲，肩部加宽 | 大盾：钢灰，一道红色斜条纹 | 盾占了大半个身体 |
| 人质 | 蓝 | 不戴头盔，浅肤色，深色头发 | 衬衫，没有任何装备 | 无 | 圆润，没有棱角分明的装备 |

共同规则：

- 头和躯干之间有一圈深色领口。
- 头盔的帽檐、护目镜都要在命中球之内或只略微超出，头部的可见不可打率 ≤ 0.10。
- 背包、弹带、肩甲这些超出命中盒的装备要薄（凸出不超过 6 厘米），否则从侧面看可见不可打率会超标。
- 人质的所有部件都是“不能打”的命中区。人质的可打不可见率 ≤ 0.08，比敌人严，因为打到看不见的地方算误伤很冤。
- 人质被挟持时严格使用T09的held姿态（下沉0.30米、双臂垂在身后），不能改用cower；站在挟持者前面，挟持者只露出头。人质的头发和挟持者的头盔不能在轮廓上连成一片，两者之间的色差由 R02 检查。

部件数量：头 5、躯干 5、手臂 3 种（标准、重甲、平民）、腿 3 种、手持物 4、盾 1，共约21个独立网格（左右镜像实例另计绘制，不重复计源网格）。爆头时飞出去的头直接复用头部网格；身体碎屑用 3 个通用碎块。

## 6. Boss：重装机甲

### 6.1 网格

部件、尺寸和命中区沿用引擎任务 T19 的表，共10个部件：两腿、髋、躯干、核心、核心盖板、两个导弹舱、主炮、头。总高约 4.2 米。

- 路线：按部件生成后配准（框架 §4.3）。整机出一张概念图定设计，再为躯干、腿、导弹舱、头、主炮各出一张部件图。保底是程序化的硬表面部件（切角盒、装甲板、铆钉、散热格栅）。
- 导弹舱和核心是琥珀色，其余是装甲色，亮面和暗面用两个灰度区分体块。躯干和肩部各加一道红色条纹，帮助从集装箱背景里分出来。
- 导弹舱是盒形弱点，正面做成蜂窝状的发射口，一眼看得出是“导弹舱”。击毁后换成一个烧黑的残桩（单独的状态网格）。
- 核心在盖板后面。盖板打开时核心完全露出；关闭时从正面完全看不到核心，与“关闭时打不动”一致。
- 不参与命中的装饰件：液压杆、天线、线缆、背部排气管。装饰件不得遮挡弱点。
- 击毁后的残骸：6 个大碎块，由部件网格切出来。

### 6.2 骨骼片段

骨架：每个部件一根骨头，加根骨和装饰件的骨头，权重全是 1。片段用关键帧表生成，烘焙成姿态轨（框架 §8.2）。

| 片段 | 长度 | 对应引擎状态 | 内容 |
|---|---|---|---|
| walk | 60 tick，循环 | 登场（3 秒走 10 米） | 两步一循环，步幅 1.67 米，与 3.33 米每秒的移动速度匹配。躯干随步伐起伏 |
| idle | 120 tick，循环 | 阶段 1、2 的待机 | 轻微起伏，炮口缓慢摆动 |
| salvo | 54 tick | 齐射前 0.9 秒的预警 | 导弹舱盖掀开，机身后坐 |
| stagger | 90 tick | 两舱全毁后的 1.5 秒硬直 | 机身摇晃、下沉，残桩冒火花的挂点 |
| charge | 150 tick 和 120 tick 两个版本 | 阶段 2、3 的蓄力 | 盖板上移 1.0 米，主炮抬起对准镜头，机身下蹲蓄力 |
| fire | 30 tick | 蓄力成功开火 | 后坐 |
| paralyzed | 120 tick | 被打断后的 2 秒瘫痪 | 机身前倾失衡，核心保持暴露 |
| advance | 45 tick，循环 | 阶段 3 前压（1.5 秒走 4 米） | 快步，步幅 1.0 米 |
| destroyed | 150 tick | 击毁后的 2.5 秒 | 跪倒、解体。此时所有部件已不可命中 |

### 6.3 对玩法的影响和限制

片段会让命中体跟着动，所以有两条硬限制：

- 弱点可以被打的期间（阶段 1 的导弹舱；蓄力和瘫痪时的核心），该弱点相对 T19 表中静态位置的位移 ≤ 0.10 米，速度 ≤ 0.3 米每秒。大幅度的动作留给装甲部件和装饰件，或者放在弱点不可打的状态里（登场、硬直、击毁）。
- 盖板的开合时间、蓄力时长、预警时长由引擎Boss行为决定，片段只能配合。charge的第0帧盖板必须已处于上移1米的开放位置；不能用整个蓄力窗口慢慢揭开。任何插值装饰不得挡住已可打核心；paralyzed全程开放，等待/切阶段立刻关闭，fire仅占用既有等待时间，不额外增加30tick。

分两步交付，降低风险：

1. **静态版**：只换网格，部件位置完全沿用 T19 的静态表。只影响画面，回放哈希不变。这一步先进审核。
2. **片段版**：接入姿态轨。之后重跑关卡校验器（含 Boss 弱点可见性）和引擎任务 T20 的机器人验收，指标必须仍然达标；重新生成回放夹具。不达标就收紧位移上限或退回静态版。

## 13. v0.2 修订与执行前条件

- 本机事实见[DEV_ENVIRONMENT.md](DEV_ENVIRONMENT.md)。本方案仍是美术设计，AF/EI/WR详细任务及机器可读规格尚未编写；不能将大纲视为已存在工具。

- 色差表是sRGB色板的静态预检，R类必须在最终渲染后测量。领口分隔不能让R02的ΔE自动通过：对投掷兵明确检查弱点与相接深色领口，并附其与躯干的原始色差；若仍不满足就修改色板/造型后重审。奖章、医疗十字的M03例外仅限本节指定资产/颜色，不能泛化到全场景。
- Boss装饰预算按左右重复部件核算：原明细按每条腿500、每个导弹舱500、装饰共800计为5500面，保留500面余量，总额≤6000，最终以导出三角形数为准。
- B1依赖Compatibility基础材质与EI06，因为首次可读性验收须用目标渲染器。框架的“移动档”是资产预算名称，所用Godot渲染方法是gl_compatibility，不是名为Mobile的另一渲染器。PC验收不能替代安卓真机验收。
- 姿态轨和美术发布遵循框架§17。B4静态版先固定通过版本，再接片段；片段失败可回退已批准静态版，不删除失败记录。
